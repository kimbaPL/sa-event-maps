SA EVENT MAPS — OCHRONA WŁAŚCICIELA PROJEKTU

USTALENIE
Pierwsze konto utworzone w Supabase Auth jest stałym właścicielem projektu.
Właściciel zachowuje rolę administratora. W panelu jego ranga ma czerwone
oznaczenie „Właściciel”, podczas gdy administratorzy pozostają zieloni,
a gracze szarzy.

PLIKI DO ZASTĄPIENIA
- index.html
- style.css
- admin-panel.js
- supabase-data.js

NOWA MIGRACJA
- supabase/migrations/20261109233000_protect_project_owner.sql

CO ZMIENIA MIGRACJA
- Dodaje kolumnę profiles.is_owner (bez tworzenia nowej tabeli).
- Wybiera najstarsze istniejące konto auth.users według created_at; przy remisie
  stosuje UUID jako deterministyczne rozstrzygnięcie.
- Przywraca temu kontu role='admin' i ustawia is_owner=true.
- Pozostałym kontom nie zmienia ról.
- Wymusza warunek: konto oznaczone jako właściciel zawsze musi mieć role='admin'.
- Wymusza maksymalnie jednego właściciela indeksem unikalnym.
- Rozszerza admin_list_users() o flagę is_owner.
- Blokuje w admin_set_user_role() próbę odebrania rangi właścicielowi.
- Odbiera rolom anon i authenticated możliwość aktualizacji kolumny is_owner.

KOLEJNOŚĆ WDROŻENIA
1. Zachowaj aktualną kopię projektu — nie usuwaj dotychczasowych kopii.
2. W Supabase SQL Editor uruchom najpierw zapytanie kontrolne z rozmowy.
   Sprawdź, czy najstarsze konto auth.users to Twoje pierwsze, główne konto.
   Nie uruchamiaj migracji, dopóki nie potwierdzisz tej zgodności.
3. Rozpakuj paczkę do głównego folderu projektu i zastąp wskazane pliki.
4. W PowerShell uruchom: node --check .\admin-panel.js
5. Uruchom: node --check .\supabase-data.js
6. Uruchom: node .\scripts\build.mjs
7. Sprawdź Git i wykonaj `npx.cmd supabase db push --dry-run --remote`.
8. Kontynuuj wyłącznie wtedy, gdy jedyną oczekującą migracją jest
   20261109233000_protect_project_owner.sql.
9. Zastosuj migrację przez `npx.cmd supabase db push --remote`.
10. Zweryfikuj is_owner i role w profiles oraz zaktualizowane funkcje.
11. Dopiero wtedy wykonaj git add, commit i push. Cloudflare wdroży frontend.
12. Po wdrożeniu odśwież stronę przez Ctrl+F5 i sprawdź czerwone oznaczenie
    właściciela oraz brak możliwości zmiany jego rangi.

WAŻNE
- Nie wykonuj db reset.
- Nie usuwaj kont testowych ani danych projektu.
- Nie zmieniaj ręcznie UUID konta właściciela.
- Migracja automatycznie przywróci rangę administratora pierwszemu kontu.
- Jeśli pierwsze konto w wyniku zapytania kontrolnego nie jest właściwym kontem,
  przerwij wdrożenie i skontaktuj się przed zastosowaniem migracji.
